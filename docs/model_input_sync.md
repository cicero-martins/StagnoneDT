# Keeping run inputs on both machines

Until 2026-09-03 seven of the eight factorial members behind Paper 1 existed
only on simit. Three of them had a local directory holding 20 GB of output and
not one input file, and the four `_veg_*` members had no local directory at all.
The manuscript rested on a single host.

`scripts/pull_model_inputs.sh` brings them back and is meant to be re-run after
every batch of runs, not once.

```bash
bash scripts/pull_model_inputs.sh --all-veg                  # inputs
bash scripts/pull_model_inputs.sh --with-restart --all-veg   # and initial state
```

## What the directories deliberately lack

The members are clones of one another. Across the seventeen pulled directories
there are 1449 MB of files and 119 MB of distinct content, and 71 MB of that is
the same eighteen files repeated in every member: the blended wind, the mesh,
the bathymetry, the ERA5 chunks, the per-node offset boundary and the turbid
discharge set. One copy is tracked, in `model/dflowfm_v04AE_nowaves/`, which is
the baseline. The pull leaves them on the wire and the pulled directories are
short of them by design, which saves 1.2 GB of working tree.

They are listed in `scripts/model_shared_inputs.txt`. Restore them before
running a member:

```bash
python scripts/complete_model_dir.py model/_veg_waves_dm
python scripts/complete_model_dir.py --check --all
```

A file earns its place on that list only while the same relative path carries
the same md5 in every member and in the baseline. The test is on the pair, never
on content alone, because a blob can appear under one name in one member and
another name elsewhere, as `sediment.sed` does against `sediment.sed.orig`.
`--check` re-tests it on every call and refuses to copy over a member that has
grown its own version.

## What is on disk but not in git

**`restart_input/`**, 649 MB in five distinct states across nine members. The
`_veg_*` members are three-day restart segments, so without it they will not
start, and it cannot be regenerated without re-running the nine-day parents. It
is bound to the eight-way METIS decomposition of the host that wrote it, so a
committed copy would be wrong anywhere else. Pull it with `--with-restart`.

Worth recording from the checksums: `_veg_hv040_3d` and `_ctrl_noveg_seg` start
from a byte-identical state, which is what makes the control in §4.1 a control.

**`wave/TMP_ESMF_RegridWeightGen_*.nc`**, the FM-mesh to SWAN-grid regrid
weights. The name says temporary and they are not. Without them SWAN aborts
before writing a log and takes the shared MPI communicator with it, so FM dies
in `MPI_Comm_size` with a null communicator and no FATAL anywhere. The pull
brings them across on purpose; git ignores them because they are bound to the
mesh, the grid and the partition count.

**Partition files** — `*_000?.mdu`, `*_000?_net.nc`, `*.cache`,
`DFM_interpreted_idomain_*`. METIS output, machine-bound, regenerated by
partitioning locally. The `[veg]` block that the setup script appends to every
partition MDU is also in the master, so the configuration is fully recorded
without them.

## What a fresh clone can and cannot reproduce

A clone plus `complete_model_dir.py` gives every input that defines a member:
the master MDU with its `[veg]` block, both `.ext`, the boundary `.bc`, the
vegetation `.xyz`, `initialFields.ini`, the trachytope `.arl` and `.ttd`, the
sediment and morphology files, `dimr_config.xml` and the SWAN grids and
boundaries. Partitioning and running follows from that.

What it cannot reproduce is the restart state the segment members start from.
That lives on disk here and on simit, and nowhere else.

## One thing the first pull corrected

The tracked `trachytopes.ttd` in the baseline was stale: it carried the old
formula numbering, 51 and 1, against the 53 and 153 the server has, and the
class column started at 0 rather than 1. The server copy is the one that ran.
Related, and the reason this matters more than a stale file usually would:
`sediment_calibration_sources` records that the number in a `TraFrm` field
cannot be trusted without reading the formula name back from the `.dia`.
